# Pilot Guide

A structured, low-risk way to evaluate LumenAI in a real environment. A pilot is a
**validation**, not a production rollout, and does not connect the public demo to
production data.

## Objectives (agree up front)
- Confirm the workflow fits the department's real process.
- Confirm evidence records are complete and reviewable.
- Confirm human-review routing matches local policy.
- Gather qualitative feedback from technicians and reviewers.

## Scope
- A bounded set of instrument types and a defined time window.
- Named roles: SPD lead, reviewer(s), quality sponsor.
- Synthetic or de-identified data during evaluation unless a data agreement is in place.

## Success signals (qualitative first)
- Technicians can document an inspection quickly and consistently.
- Reviewers can act on routed findings with the evidence provided.
- Quality can assemble an audit-ready record without spreadsheet archaeology.

## Out of scope for a pilot
- Any claim of clinical outcome, infection reduction, or diagnostic performance.
- Replacing existing review, IFUs, or infection-prevention judgment.

## Exit
A written readout: what worked, what to change, and a go/no-go for a wider rollout.
